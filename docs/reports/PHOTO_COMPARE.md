# Before/after Photo preview — production milestone

Date: 10 October 2026 UTC. [PR #11](https://github.com/rlawoals0529/Astralys/pull/11), merge `d99000da260e8a910670f168c1a991034500a316`. No deployment and no repository visibility change.

## Outcome

Photo Studio now has an honest, toggleable **side-by-side Original / Edited comparison**. A keyboard-operable `Compare original` control uses `aria-pressed` and changes to `Close comparison` when active. On larger screens it displays the two previews in adjacent panes; on narrower screens the preview panes stack to avoid horizontal overflow. The edited image remains capable of the existing crop-position pointer gesture.

The **Before** view is the **first sanitized, metadata-stripped PNG preview** generated by Astralys's existing dedicated image worker, not the user's original untrusted image or a byte-for-byte/color-managed rendering. It is cached only as an in-memory Blob URL and remains unchanged across subsequent rotation, crop, flip, undo/reset, image exports and PDF exports. This means the comparison may not represent original EXIF orientation, color profiles or exact source encoding. The **After** image uses the already existing edited-preview Blob URL.

The new `ObjectUrlSlot` is independent from the edited-preview and export URL slots. Its source is set **once** after successful initial inspection; it is revoked on file replacement, explicit clear and pagehide. On unsupported or malformed images no original preview is exposed. The comparison mode resets on a new file. Toggling comparison performs **no extra file decode, network request, upload, storage write, telemetry or export mutation**, and does not add entries to the undo history.

The UI deliberately avoids a synchronized-zoom or pixel-accurate slider claim because the original and edited images can have different orientations and aspect ratios.

## Roadmap and guardrails

New [prioritized product roadmap](../product/ROADMAP.md) favors bounded local batch image conversion, tonal/color adjustments, export presets, permanent visual redaction and eventual multi-page image-to-PDF. Feature scope and legal/security gates remain explicit; do not add nonfunctional placeholders.

Still unresolved: name review, full Git-history security inspection, verified vulnerability-reporting channel, real-world photographic samples, manual assistive-tech check, Chrome/Firefox process-memory profiling and a public preview gate. See [source release issue #8](https://github.com/rlawoals0529/Astralys/issues/8). REA stays a developer-only opt-in command requiring separate installation. PhotoCraft remains an isolated, pinned WASM color/compositing feasibility spike; it is **not** the production editor.

**Next practical vertical slice:** batch still-image conversion with per-file errors, bounded queue/worker lifetime, and a controlled download strategy; avoid flooding browser download prompts or importing unreviewed archive libraries.
